# Phase 01 — Virtiofsd lifecycle in cluster-ctl

> **Recommended Codex model: GPT 5.5 high**
>
> This phase fixes a process-lifecycle bug that touches subprocess management,
> Unix socket readiness, cleanup-on-failure paths, and a NixOS module
> assertion. None of the individual edits is large, but the boundary
> conditions (socket-race, partial-startup, stop-instance reaping both
> children, kvm-group preflight) require careful sequencing. A `medium`-tier
> agent will likely miss the cleanup edge cases on the cleanup paths in
> `microvm_start` and `login_single_vm`. `max` is overkill — there is no
> design ambiguity left after the dossier.

## Working tree

`/data/nvme0/can/Projects/steampipe` (the steampipe repo). The runtime side
of the work is exercised against the atlas host's installed runners at
`/etc/steampipe/login-runners`; do not edit those store paths directly.

## Goal

`cluster-ctl steam login vm-1` (or any login-class VM) boots the VM
successfully: the per-VM virtiofsd process is started before QEMU, the
virtiofs socket exists when QEMU connects to it, SSH becomes reachable within
`LOGIN_SSH_TIMEOUT_SECS`, and `cluster-ctl down` later reaps both processes
without leaks. The host operator user (`tapOwner`, typically `can` on atlas)
can run this without `sudo`.

## Why this matters now

Today the login flow fails at the first VM with:

```
microvm@vm-1: -chardev socket,id=fs0,path=vm-1-virtiofs-steam-state-vm-1.sock:
Failed to connect to 'vm-1-virtiofs-steam-state-vm-1.sock':
No such file or directory
```

Source: `vm.log` tail from a real `cluster-ctl steam login all` run captured
in the research dossier
([../headless-steam-login-research.md](../headless-steam-login-research.md)).

Cause: `microvm_start` in
[src/core/backend.rs:243-277](../../../src/core/backend.rs#L243-L277) spawns
only `bin/microvm-run` (a QEMU command line that opens
`-chardev socket,…` immediately). The sibling `bin/virtiofsd-run` —
generated by microvm.nix and present at
`/etc/steampipe/login-runners/<vm>/bin/virtiofsd-run` — is the only thing
that creates that socket, and nothing in the orchestrator ever invokes it.
The NixOS module installs the link-farm but does not install per-VM systemd
services either ([nix/module.nix:497-548](../../../nix/module.nix#L497-L548)).

Until this is fixed, **every** later phase (parallel login, docs refresh)
cannot be validated end-to-end against a real cluster.

## Out of scope

- Do not change the runner-class split. Regular runners stay
  virtiofs-free; login runners keep the writable steam-state share. The
  dossier resolves this in "Decisions baked into this plan".
- Do not switch to per-VM systemd units. We are intentionally keeping the
  in-process orchestration path so `cluster-ctl` stays self-contained.
- Do not parallelize `steam::login` here. Phase 02 owns that.
- Do not touch docs here. Phase 03 owns that.
- Do not modify the supervisord config or the generated virtiofsd script
  in-place. Use the existing `bin/virtiofsd-run` wrapper as-is.

## Plan

1. **Confirm the runner shape on the atlas host** before editing anything.
   Read `/etc/steampipe/login-runners/vm-1/bin/microvm-run` and
   `bin/virtiofsd-run`. Note that `microvm-run` is invoked from `current_dir
   = microvm_state_dir(state_dir, vm)` (per
   [src/core/backend.rs:261](../../../src/core/backend.rs#L261)) and creates
   the socket *relative to its CWD*. Virtiofsd must therefore inherit the
   same `current_dir` so the socket lands where QEMU expects.

2. **Extend `microvm_start` in
   [src/core/backend.rs:243-277](../../../src/core/backend.rs#L243-L277)** to:
   - Compute `virtiofsd_runner = runners_dir.join(&vm.name).join("bin/virtiofsd-run")`.
   - If the file exists, spawn it as a child process with:
     - `current_dir(&vm_dir)` (same as the microvm-run cwd),
     - `env("XDG_RUNTIME_DIR", &runtime_dir)`,
     - stdio piped to a sibling log file under
       `microvm_state_dir(state_dir, vm)` — suggest `virtiofsd.log` next to
       `vm.log`,
     - `process_group(0)` so it is killable as a group.
   - Inspect the runner directory once to enumerate the socket file name(s)
     declared by the runner. The simplest reliable trick is to grep
     `bin/microvm-run` for `path=vm-N-virtiofs-*.sock` and collect those
     names. Cache the result so we don't re-grep on every wait iteration.
   - Wait (≤ 10 s, 100 ms poll) for each socket file to exist in
     `vm_dir`. If timeout fires, kill the virtiofsd child, propagate a clear
     error (`"virtiofsd never created socket {path}"`), and return.
   - Only after sockets are present, spawn `microvm-run` as today.
   - Persist the virtiofsd PID alongside the microvm PID so `microvm_stop`
     can reap it. Add a second slot to `src/core/state.rs`
     ([src/core/state.rs](../../../src/core/state.rs)): suggest a
     `<vm>.virtiofsd.pid` file mirroring the existing `<vm>.pid` shape.

3. **Extend `microvm_stop` in
   [src/core/backend.rs:279-295](../../../src/core/backend.rs#L279-L295)** to:
   - Before the existing `pkill -f microvm@<vm>` line, read the virtiofsd
     PID file. If the PID is alive, kill it (TERM, wait briefly, then KILL).
   - Remove the virtiofsd PID file regardless.
   - After both children are stopped, the existing `cleanup_microvm_sockets`
     call already handles the leftover socket files
     ([src/core/backend.rs:351-364](../../../src/core/backend.rs#L351-L364))
     — verify it also matches the new `*-virtiofs-*.sock` names; the
     `state::is_socket_file` test
     ([src/core/state.rs](../../../src/core/state.rs)) may need a one-line
     extension to recognise `.sock` files with the virtiofs prefix.

4. **Confirm the operator can satisfy `--socket-group=kvm`.** Two acceptable
   paths; pick whichever the operator's host already supports:
   - **Preferred:** ensure `tapOwner` is in `kvm`. Add an assertion to
     [nix/module.nix](../../../nix/module.nix) (alongside the existing
     `loginRunners.enable` assertions around
     [nix/module.nix:370-409](../../../nix/module.nix#L370-L409)) that
     warns if `cfg.tapOwner != null` and the resolved user lacks `kvm`
     group membership. Pure-eval cannot read the system's group DB, so this
     has to be a `lib.mkIf cfg.loginRunners.enable`-gated `warnings`
     entry (see
     [nix/module.nix:467-473](../../../nix/module.nix#L467-L473)) plus a
     prose hint in `services.steampipe-cluster.loginRunners.enable`'s
     description.
   - **Fallback for hosts that cannot add the user to kvm:** spawn
     virtiofsd-run with `STEAMPIPE_VIRTIOFSD_NO_SOCKET_GROUP=1` and have
     `cluster-ctl` write a one-shot override file that strips
     `--socket-group=kvm` before invoking the upstream wrapper. **Do not
     implement this fallback in this phase unless the assertion fails on
     the operator's host.** Document it as a TODO comment in `backend.rs`
     and stop.

5. **Add a focused Rust test** in
   [src/core/backend.rs](../../../src/core/backend.rs) tests module that:
   - Builds a fake `runners_dir/vm-1/bin/{microvm-run,virtiofsd-run}` shell
     pair (the virtiofsd stub just `touch`es the expected socket file then
     `sleep`s; the microvm stub asserts the socket exists then exits 0).
   - Calls `microvm_start` against this fake runner and asserts the
     microvm child exits 0.
   - Calls `microvm_stop` and asserts both PID files are removed and both
     stub processes have exited.
   - Use `tempfile::TempDir` for `state_dir` / `runners_dir`. The existing
     `cleanup_microvm_sockets_preserves_non_socket_files` test
     ([src/core/backend.rs:593-609](../../../src/core/backend.rs#L593-L609))
     is the closest pattern to mimic.

6. **Smoke-run on the atlas host.** With this phase's changes built:
   ```bash
   nix run .#cluster-ctl -- --vm-count 1 steam login vm-1 --force
   ```
   Watch for:
   - `Waiting for SSH... ready`,
   - SteamCMD bootstrap output following without `STEAMCMD_TMUX_MISSING`,
   - `cluster-ctl down` cleanly stops both processes (`ps aux | grep -E
     'virtiofsd-steam-state-vm-1|microvm@vm-1'` returns nothing).

## Acceptance criteria

- [ ] `nix build .#cluster-ctl` builds without warnings.
- [ ] `cargo test -p steampipe backend::tests` passes; the new
      virtiofsd-lifecycle test is present and green.
- [ ] On atlas, `cluster-ctl steam login vm-1 --force` reaches
      `Waiting for SSH... ready` within 90 s and completes the SteamCMD
      bootstrap step. `vm.log` for `vm-1` contains no
      `Failed to connect to '*.sock'` lines.
- [ ] After `cluster-ctl down`, `pgrep -af 'virtiofsd-steam-state-vm-1'`
      returns nothing and `~/.local/state/steampipe/<cluster>/vm-1/` contains
      neither `vm-1.pid` nor `vm-1.virtiofsd.pid` (or the new PID file name
      chosen).
- [ ] The NixOS module emits a clear warning (or assertion failure) when
      `loginRunners.enable = true` and the resolved `tapOwner` cannot
      satisfy the kvm socket-group requirement — verified by reading the
      module diff and running `nixos-rebuild build` on a test config.
- [ ] No regression in `cluster-ctl up` / `cluster-ctl warm` /
      `cluster-ctl steam check` against the regular (non-login) runners —
      they have no virtiofs share, so the new code path must short-circuit
      cleanly when `bin/virtiofsd-run` is absent. Confirm with a manual
      `cluster-ctl up` against `./result` and check no errors in `vm.log`.

## Pitfalls

- **Socket-race timing.** Virtiofsd may take 100–500 ms to bind the socket
  on a cold runner. Spawning QEMU before the socket exists reproduces the
  original bug. The 10 s/100 ms poll is generous; do not lower it for
  perceived snappiness. Symptom: intermittent
  `Failed to connect to '*.sock'` under load. Recovery: keep the poll;
  consider widening if `vm.log` shows races under parallel boots in
  Phase 02 testing.
- **Socket lookup hard-coding.** Do not hard-code
  `vm-{N}-virtiofs-steam-state-vm-{N}.sock` in Rust — the runner script
  is the source of truth and may declare additional shares in future. Grep
  `bin/microvm-run` for `path=([^,]*\.sock)` and use the results. Symptom:
  silently missing a share. Recovery: enumerate from the runner.
- **Cleanup on partial start.** If virtiofsd spawned but the socket never
  appeared, you must kill it before bailing. Otherwise repeated
  `steam login` invocations leak virtiofsd processes. Symptom: `pgrep
  virtiofsd-steam-state-vm-1` shows multiple PIDs. Recovery: a `defer`-style
  cleanup that fires on every error return inside `microvm_start`.
- **`process_group(0)` interaction with `pkill`.** The existing
  `microvm_stop` uses `pkill -f microvm@<vm>` to catch crash-recovered
  PIDs. Make sure the new virtiofsd-PID kill happens *first*; if you
  `pkill microvm@<vm>` while virtiofsd is still alive, QEMU exits but
  virtiofsd stays around because its argv has no recognisable per-VM tag
  beyond the share name. Symptom: lingering virtiofsd. Recovery: kill by
  recorded PID, then fall back to `pkill -f 'virtiofsd-steam-state-vm-<N>'`.
- **NixOS pure-eval cannot inspect group membership.** The assertion has
  to be eval-time conservative — either a `warnings` entry that the
  operator sees on `nixos-rebuild` (acceptable) or runtime-side guidance
  printed by `cluster-ctl` when the socket creation fails with EPERM.
  Symptom: silent failure if the user ignored the warning. Recovery:
  catch the virtiofsd-startup EPERM in Rust and print a one-line
  remediation hint (`"add ${user} to the kvm group: services.users.users
  .<user>.extraGroups = [\"kvm\"]"`).
- **`microvm.nix` upgrades may change the share-socket naming scheme.**
  The current scheme is `<vm>-virtiofs-<tag>.sock`. If a flake bump changes
  it, our grep needs to keep pace. Symptom: zero sockets enumerated;
  virtiofsd starts but QEMU fails the same way as today. Recovery: surface
  the empty-enumeration case as an explicit error, not a silent skip.
