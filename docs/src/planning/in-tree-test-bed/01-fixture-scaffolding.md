# Phase A — Scaffold an in-tree test fixture for the cluster

> **Recommended Codex model: GPT-5.4 / medium effort**
>
> Moderate-complexity sub-agent role: build a Nix flake that consumes
> the in-tree `mkTestCluster` library, generate test keys, write a
> minimal `steampipe.toml`, and verify the fixture boots a real VM with
> `cluster-ctl up`. The work is bounded but spans Nix evaluation,
> microvm runner generation, and basic SSH plumbing — too many moving
> parts for mini-tier, but not novel enough to justify 5.5.

## Working tree

`/data/nvme0/can/Projects/steampipe`. All new files live under a new
`tests/fixture/` subdirectory. No external repos. Independent of every
existing planning phase (`vnc-visual-testing/01..07`) — this fixture is
the *test bed* on which those phases are validated, not a consumer.

## Goal

`nix run /data/nvme0/can/Projects/steampipe/tests/fixture#cluster-1v1-up`
boots a single NixOS microVM that:

- accepts SSH on `10.0.100.1:22` using the fixture's ed25519 key,
- has `sway`, `wayvnc`, `foot`, `grim`, `vulkan-tools`,
  `wayland-utils`, and `wf-recorder` available,
- has `microvm.graphics.enable = true` (default flavor) so virtio-gpu
  paints to a real DRI device,
- exposes a `uifull` flavor that mirrors the regicide UI-full config
  for parity testing.

`cluster-ctl --vm-count 1 --project-root tests/fixture status`
reports the VM as `UP / SSH OK` within 30 s. `cluster-ctl down` cleans
it up. No game, no Steam, no host-side deployment in this phase —
just a known-good cluster boot.

## Why this matters now

Today every diagnostic and integration path for the visual-testing
plan routes through the downstream regicide checkout
(`/data/nvme0/can/Projects/solo/game-dev/regicide`). That coupling
means a steampipe-side bug is indistinguishable from a Bevy/wgpu bug
in the consumer; see
[../../migration-baseline/smoke-status.md](../../migration-baseline/smoke-status.md):

```text
NO_PROGRESS_TIMEOUT (local: 602s without semantic progress > 600s)
Unable to find a GPU!
```

The above failure is *probably* downstream, but with the current setup
we cannot prove it: the steampipe repo itself does not boot a cluster
without a consumer providing `steampipe.toml`, an SSH key, and a
runner derivation. This phase removes that coupling. After it lands,
phases A through G of the visual-testing plan can be developed,
tested, and reviewed entirely within this repo using deterministic
workloads (phase B of this plan), and any subsequent regicide failure
becomes a clear "consumer-side issue" or "regression in this fixture's
golden capture".

The in-tree flake already exposes the building blocks:
`lib.mkTestCluster` ([flake.nix:144](../../../../flake.nix#L144)),
`nixosModules.cluster-vm-base`, `nixosModules.vm-graphics`,
`overlays.default`. They've never been exercised inside this repo —
this phase wires them up.

## Out of scope

- Workloads (foot banner, vkcube, wgpu probe). Those are phase B of
  this plan.
- Capturing golden images. Phase C.
- Any `justfile` recipes or diagnostic automation. Phase D.
- Changing `mkTestCluster`, `cluster-vm-base.nix`, or
  `vm-graphics.nix`. The fixture is a pure *consumer* — if those need
  fixes, file separately and treat them as upstream blockers.
- Multi-VM scenarios. One VM is enough for diagnostic work; expand
  later if the visual-testing plan demands it.
- Login-image flavor. Steam login is out of scope; this fixture does
  not authenticate to Steam.
- CI integration. Local-only for now.

## Plan

1. **Create `tests/fixture/` directory layout.**
   ```
   tests/fixture/
   ├── flake.nix
   ├── flake.lock           (generated by step 5)
   ├── steampipe.toml
   ├── cluster_key
   ├── cluster_key.pub
   └── README.md
   ```
2. **Generate the test SSH keypair.**
   ```bash
   cd /data/nvme0/can/Projects/steampipe/tests/fixture
   ssh-keygen -t ed25519 -f cluster_key -N '' -C 'steampipe-in-tree-fixture'
   chmod 600 cluster_key
   ```
   Commit both files. Add a `README.md` paragraph explaining the key
   grants access *only* to ephemeral host-private bridge VMs and has
   no real-world authorization — this kills the "you committed a
   private key" review reflex.
3. **Write the minimal `steampipe.toml`** for the fixture:
   ```toml
   binary_name = "steampipe-fixture-noop"
   cargo_package = "steampipe-fixture-noop"   # never built — deploy disabled in phase A
   vm_user = "fixture"
   remote_dir = "/home/fixture/work"
   ssh_key = "cluster_key"
   max_vms = 1

   [network]
   bridge = "br-fixture"
   subnet = "10.0.100"
   prefix = 24
   host_ip = "10.0.100.254"
   udp_port = 27200

   [cluster]
   name = "fixture"
   graphics = true

   [cluster.flavors.uifull]
   graphics = true
   gpuProfile = "venus"
   memory = 4096
   useSystemdStage1 = false
   ```
   Adjust field names to whatever the current
   [src/core/config.rs](../../../../src/core/config.rs) and
   [nix/lib/test-cluster.nix](../../../../nix/lib/test-cluster.nix)
   actually accept — read both before writing the toml; do not guess
   from this snippet.
4. **Write `tests/fixture/flake.nix`.** Skeleton:
   ```nix
   {
     description = "In-tree test fixture for steampipe cluster validation";
     inputs = {
       nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";
       steampipe.url = "path:../..";
       flake-utils.url = "github:numtide/flake-utils";
     };
     outputs = { self, nixpkgs, steampipe, flake-utils, ... }:
       flake-utils.lib.eachDefaultSystem (system: let
         pkgs = import nixpkgs {
           inherit system;
           overlays = [ steampipe.overlays.default ];
         };
         clusterApps = steampipe.lib.mkTestCluster {
           inherit pkgs;
           inherit (pkgs) lib;
           steampipe = steampipe;
           clusterCtl = steampipe.packages.${system}.default;
           projectRoot = ./.;
           projectConfig = builtins.fromTOML (builtins.readFile ./steampipe.toml);
         };
       in {
         apps = clusterApps;
         packages = clusterApps;
       });
   }
   ```
   The exact call shape for `mkTestCluster` is defined in
   [nix/lib/test-cluster.nix](../../../../nix/lib/test-cluster.nix) —
   read its top-of-file signature and adjust args. Do not invent
   args.
5. **Lock the flake.** `nix flake lock` in `tests/fixture/`. Commit
   the resulting `flake.lock`.
6. **Smoke-build a single VM runner.** `nix build
   ./tests/fixture#cluster-1v1-up.program --no-link --print-out-paths`
   must succeed. If the attribute path differs (it depends on what
   `mkTestCluster` names its outputs), use `nix flake show
   ./tests/fixture` to list real names and update step 7 accordingly.
7. **Boot the VM.**
   ```bash
   sudo nix run ./tests/fixture#cluster-fixture-net-up || \
     sudo /data/nvme0/can/Projects/steampipe/target/release/cluster-ctl \
       --project-root tests/fixture --vm-count 1 net-up
   nix run ./tests/fixture#cluster-1v1-up
   ```
   Confirm SSH reaches ready (the `up` wrapper waits internally; if it
   exits non-zero with "SSH timeout", investigate before continuing).
8. **Verify with `cluster-ctl status`.**
   ```bash
   cargo run --release -- --project-root tests/fixture --vm-count 1 status
   ```
   Expect a one-row table showing `vm-1 / 10.0.100.1 / UP / OK`.
9. **Verify SSH into the VM directly.**
   ```bash
   ssh -i tests/fixture/cluster_key -o StrictHostKeyChecking=no \
     fixture@10.0.100.1 'which sway wayvnc foot grim vulkaninfo'
   ```
   All five paths must resolve. If any are missing, the fixture's
   NixOS config does not pull in the needed module — adjust the
   `steampipe.toml` flavor config or document the gap and escalate to
   `cluster-vm-base.nix`.
10. **Verify clean teardown.**
    ```bash
    cargo run --release -- --project-root tests/fixture --vm-count 1 down
    sudo cargo run --release -- --project-root tests/fixture --vm-count 1 net-down
    ```
    Confirm no orphan microvm processes (`pgrep -af microvm@`), no
    leftover sockets in `$XDG_STATE_HOME/steampipe/fixture/`.
11. **Document.** Fill in `tests/fixture/README.md` with: what the
    fixture is, what it isn't (no game, no Steam), how to boot,
    how to tear down, where to find runner outputs, the test-key
    disclaimer.

## Acceptance criteria

- [ ] `tests/fixture/flake.nix` evaluates: `nix flake show
      ./tests/fixture` exits 0 and lists at least
      `apps.x86_64-linux.cluster-1v1-up`, `cluster-1v1-down`,
      `cluster-fixture-net-up`, `cluster-fixture-net-down` (or
      equivalent names produced by `mkTestCluster`).
- [ ] `nix build ./tests/fixture#cluster-1v1-up.program --no-link`
      succeeds within 10 minutes on a cache miss; under 1 minute on
      a warm cache.
- [ ] `nix run ./tests/fixture#cluster-1v1-up` boots a VM whose SSH
      becomes reachable within 30 s of the runner starting.
- [ ] `ssh -i tests/fixture/cluster_key fixture@10.0.100.1 -- \
      uname -a` returns a NixOS uname string.
- [ ] `cluster-ctl --project-root tests/fixture --vm-count 1 status`
      shows `vm-1 / UP / OK`.
- [ ] All of `sway`, `wayvnc`, `foot`, `grim`, `vulkaninfo`,
      `wayland-info`, `wf-recorder` resolve to non-empty paths
      inside the VM.
- [ ] `down` + `net-down` produce no orphan processes
      (`pgrep -af microvm@ | wc -l` == 0) and no leftover sockets
      (`find $XDG_STATE_HOME/steampipe/fixture -name '*.sock'`
      empty).
- [ ] `tests/fixture/README.md` exists and explains the test-key
      disclaimer, the boot/down commands, and what each flavor
      (`default`, `uifull`) provides.
- [ ] `cargo test --workspace` still green (no Rust code touched
      by this phase, so this should be trivially true; verify
      anyway).

## Pitfalls

- **`mkTestCluster` argument signature drift.** The library is
  hand-written and not yet exercised in-tree, so it likely has
  undocumented required args. Symptom: `error: function … called
  without required argument 'X'`. Recovery: open
  [nix/lib/test-cluster.nix](../../../../nix/lib/test-cluster.nix)
  and read the `{ … }:` parameter list at the top. Match exactly.
- **`path:../..` self-reference creates dirty trees in CI.** Nix
  resolves `path:../..` against the *current* worktree state,
  including uncommitted files. That's fine locally; in CI add
  `--impure` or pin via `git+file:` once the fixture is merged.
- **SSH host-key prompts on first connect.** `cluster-ctl` already
  passes `StrictHostKeyChecking=no` but if you SSH manually, expect
  a prompt. Add the `-o StrictHostKeyChecking=no -o
  UserKnownHostsFile=/dev/null` pair to ad-hoc commands.
- **Bridge naming collision.** If the regicide cluster is up on
  `br-cluster` and this fixture defaults to `br-fixture`, they
  coexist. If you reuse `br-cluster`, expect routing chaos. Pin a
  distinct bridge name in `steampipe.toml`.
- **NixOS state version mismatch.** `cluster-vm-base.nix` pins
  `system.stateVersion = "25.05"`. If nixpkgs has moved much, you
  may see warnings — they are not blockers. Note any unexpected
  module-deprecation warnings in the README rather than silencing
  them.
- **`wf-recorder` and `wayland-utils` may not be in the base VM
  yet.** Phase C of `vnc-visual-testing` adds `wayland-utils`;
  phase G adds `wf-recorder`. If they aren't on the VM PATH now,
  either accept that and revisit during those phases, or add them
  here in `cluster-vm-base.nix`. **Decision:** add them in
  `cluster-vm-base.nix` as part of *this* phase if the fixture
  needs them for downstream phases of this plan. Document the
  upstream module change in the PR description.
- **`graphics = true` in default flavor.** Confirms virtio-gpu is
  wired. If `nix/lib/test-cluster.nix` defaults this to `false`,
  set it explicitly to `true` in the toml; do not rely on
  inferred defaults.
